# Gooner 第5期 個人PL・インセンティブ管理ダッシュボード

合同会社Gooner 第5期（2026年8月〜2027年7月）の事業部別PL・個人PL・インセンティブを、Googleスプレッドシートを DB として可視化・自動計算する Next.js アプリです。

- **現場報告 → 承認 → PL自動反映**: 人材（入社決定）・営業（BAR売上）・運送（稼働）を各自がアプリから報告し、統括/本部が承認すると PL・インセンティブへ即時反映
- **給与見立てのセルフ解決**: 各メンバーが「今月の支給額」「翌月の支給見込み」「半期ボーナス（実績ベース/着地見込み）」を自分で確認
- **経営会議モード**: 予実対比、12ヶ月推移、年間目標（5,000万〜6,000万）への着地見込みを全画面・拡大表示で投影

## セットアップ

```bash
npm install
npm run dev        # http://localhost:3000
```

Google Sheets 未設定の場合は、サンプルデータ（プロトタイプの数値）で `.data/db.json` に保存しながら動作します。ヘッダーの「視点」セレクトで ADMIN / LEADER / MEMBER の見え方を切り替えられます（開発モードのみ）。

### Google Sheets 連携

1. Google Cloud でサービスアカウントを作成し、Sheets API を有効化、キー(JSON)を発行
2. 対象スプレッドシートをサービスアカウントのメールアドレスに「編集者」で共有
3. `.env.example` を `.env.local` にコピーして `GOOGLE_SHEET_ID` と認証情報を設定
4. シートを作成（必要ならサンプルデータも投入）

```bash
npm run sheets:init            # 不足しているシート・列を作成（既存データは変更しない）
npm run sheets:init -- --seed  # 空のシートにサンプルデータを投入
```

各シートの1行目は列名（`member_id` など）です。列の並び順は自由で、列名で読み書きします。

## 構成

```
src/
  lib/
    types.ts            DBスキーマの型（仕様書 §3 ＋ 拡張列）
    constants.ts        期・事業部・設定パラメータ既定値
    finance-engine.ts   計算ロジック（仕様書 §4）※純粋関数、サーバー/クライアント共通
    access.ts           権限マトリクス（仕様書 §5）
    view-model.ts       権限別に絞り込んだ画面データの組み立て
    google-sheets.ts    Sheets API クライアント
    db/                 シート定義とリポジトリ（Sheets / ローカルJSON）
    seed.ts             サンプルデータ
  app/api/              Route Handlers（下表）
  components/dashboard  画面（概要・推移・日次・事業部・個人PL・承認・マスター）
scripts/sheets-init.ts  シート初期化
```

| API | 内容 | 権限 |
| --- | --- | --- |
| `GET /api/dashboard?month=YYYY-MM` | 権限別に絞り込んだ集計済み画面データ | 全員 |
| `POST /api/transactions` | 売上実績の報告（ADMIN は即時確定、他は承認待ち） | 本人/統括/本部 |
| `PATCH /api/transactions/:id` | 承認・差戻し | 統括（自事業部の他者分）/本部 |
| `POST /api/referrals`・`PATCH /api/referrals/:id` | リファーラル登録・承認 | 登録: 本人/統括/本部、承認: 本部 |
| `POST /api/expenses` | 経費実績の登録 | 統括（自事業部）/本部 |
| `PUT /api/master` | 事業計画・パラメータ・メンバー更新 | 本部 |
| `GET /api/data` | 全データ取得（バックアップ用） | 本部 |

権限による絞り込みはすべてサーバー側で行い、閲覧権限のないデータ（他人の給与など）はブラウザに送られません。

## 仕様書からの主な変更・追加

| 項目 | 内容 |
| --- | --- |
| 承認フロー | `04_T_売上実績` / `06_T_リファーラル` に `status`（PENDING/APPROVED/REJECTED）・`created_by`・`approved_by` 等を追加。承認済みのみ PL に反映。統括は自分の報告を自己承認できない |
| メール列 | `01_M_メンバー` に `email` を追加（本番ログインとの紐付け用） |
| 固定費 | プロトタイプの事業部別固定費を `03_M_設定パラメータ`（`fixed_cost_sales` 等）に移動。変動経費は `05_T_経費実績` |
| リファーラル | `06_T_リファーラル` に一本化。社内送客は送客先事業部の売上から紹介元へ振替（全社売上は二重計上しない）。社外（引越し等）は `to_dept=EXTERNAL` で紹介元に配分額のみ計上 |
| 支給タイミング | インセンティブを「発生月」と「支給月（翌月末・翌々月15日）」で管理し、「今月の支給額」を正しく算出 |
| 半期ボーナス | 実績ベース（現時点）と着地見込み（残り月を事業計画で補完）の2本立て |
| 日次進捗 | 月の日数・今日の日付から経過日数を算出（プロトタイプの 29日/31日 固定を修正） |
| 目標計画値 | `target_cost` は `target_sales − target_op` で算出（シートには持たない） |
| デザイン | ダークモード、会議モード（全画面・拡大）、スマホ表示、Recharts によるグラフ、承認待ちバッジ |

## 計算ロジックの解釈（要確認事項）

仕様書で読み方が分かれる箇所は以下のように実装しています。変更が必要な場合は `src/lib/finance-engine.ts` とテストを修正してください（料率・閾値はマスター設定画面から変更可能）。

1. **営業 半期ボーナス**: `max(0, 半期利益×10% − 支給済BARインセン) ＋ max(0, 半期利益 − 目標)×20%`（目標超過時も10%部分は維持し、超過分に20%を上乗せ）
2. **営業 半期目標**: 上期は仕様書の 8,120,000円（事業計画の合計は 8,221,090円）。下期はパラメータ 0 のため事業計画の合計を使用
3. **人材 事業部ボーナス**: `min(利益, 目標)×3% ＋ 超過分×5%`
4. **人材 個人営業利益**: 個人売上 − マスターキー20% − 直接経費 − 月20万円の固定費配賦（プロトタイプの 200,000 を踏襲）。統括・CA とも対象
5. **決定手当**: `CA入社決定` の伝票のみ対象。流入経路 REFERRAL は3万円、それ以外（広告・直接）は1万円
6. **運送 インセン**: 運送事業部全体の営業利益を「大和利益」とみなし、月次で赤字の月は0
7. **インセン・ボーナスの受取人**: 各事業部の LEADER（在籍中の1人目）
8. **半期ボーナスの支給月**: 半期末の翌月末（上期 → 2027年2月、下期 → 2027年8月）
9. **月途中の固定費**: 当月分の固定費は月初から全額計上（月中は営業利益が低く見える）

## 本番運用に向けて残っていること

- **ログイン認証**: 現在は開発用の視点切替のみ。`AUTH_MODE=locked`（本番の既定）では誰もログインできない安全側の設定です。Google ログイン（Auth.js 等）を導入し、`01_M_メンバー.email` と突合する実装が必要です（`src/lib/auth.ts` の `getCurrentUser` を差し替え）
- 伝票の修正・削除機能（現状は差戻し → 再報告）
- 変更履歴（誰がいつ何を承認・変更したか）の監査ログシート
